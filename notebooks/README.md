# Notebooks — step-by-step teaching breakdowns

One notebook per technique *family*, each a from-scratch walkthrough of how the
method works, ending with the **real** evaluation harness run live on it. These
are the teaching companion to the production library in
[`src/courserec/`](../src/courserec/) — see
[ADR-0014](../docs/adr/0014-teaching-notebooks.md) for the design.

## What these notebooks are (and aren't)

- **They reimplement each technique from primitives** (numpy / scikit-learn) so
  every step is visible — that's the point, not a wrapper around `.fit()`.
- **They reuse the library only for plumbing** that isn't the lesson: loading the
  catalog (`courserec.data`) and the eval harness (`courserec.eval`). Numbers come
  from the same harness as the leaderboard, so the from-scratch code and the
  library are cross-checked, not divergent.
- **They are not the source of truth for results** — `scripts/run_eval.py` is.
  A notebook runs the harness on *its* technique to teach; the canonical board is
  the leaderboard.

`nbtools.py` holds the few shared display helpers (pretty result tables,
from-scratch-vs-library agreement, CI plots); it is ordinary linted, unit-tested
code (`tests/test_nbtools.py`).

## Running them

```bash
pip install -e ".[notebooks,semantic]"          # tooling + the semantic rungs

# Interactive: pair .py <-> .ipynb and open in Jupyter
jupytext --to ipynb notebooks/01_lexical.py
jupyter lab notebooks/01_lexical.ipynb

# Headless / CI: generate, then execute every notebook (fails on any cell error)
jupytext --to ipynb notebooks/*.py
pytest --nbmake --nbmake-timeout=300 notebooks/*.ipynb
```

> **The `.py` percent scripts are the versioned source** (clean git diffs). The
> `.ipynb` are generated by jupytext and **gitignored** — never edit or commit
> them. Notebooks run from any directory (paths resolve via the installed
> package) and stay fast by loading fitted models from `artifacts/` (warm).
